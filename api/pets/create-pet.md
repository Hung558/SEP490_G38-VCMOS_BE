# API Documentation: Create Pet

Create a new pet that belongs to the logged-in user. The pet `code` is generated by the server.

## Endpoint

| | |
|---|---|
| **Method** | `POST` |
| **URL** | http://localhost:9999/api/pets |
| **Auth** | Required: `Authorization: Bearer <token>` (token from the login API) |
| **Content-Type** | `multipart/form-data` (when uploading a photo) or `application/json` (no photo) |

## Request body

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | Yes | Pet name. Trimmed, max 100 characters. |
| `species` | string | No | Species, e.g. `Dog`, `Cat`. Trimmed, max 50 characters. |
| `breed` | string | No | Breed. Trimmed, max 50 characters. |
| `coatColor` | string | No | Coat colour. Trimmed, max 50 characters. |
| `notes` | string | No | Free-text notes. Trimmed, max 1000 characters. |
| `dob` | string | No | Date of birth, e.g. `2021-03-15` or a full ISO 8601 date-time. Must not be in the future. |
| `weight` | number | No | Weight in kg, from `0` to `500`. A numeric string (e.g. `"4.2"`) is accepted, which is what `multipart/form-data` sends. |
| `photo` | file | No | Photo file. **Must be sent as a file in a `multipart/form-data` request** with the field name `photo`. JPEG, PNG or WebP, max 5 MB. |

Notes:

- Optional fields sent as an empty string (or `null` in JSON) are ignored.
- `code`, `ownerId` and `status` cannot be set by the client. Any such fields are ignored: `code` is generated as `PET-` + 6 characters, `ownerId` is the logged-in user, and `status` starts as `Active`.
- A `photo` key inside a JSON body is ignored. To upload a photo, use `multipart/form-data`.
- The photo format is checked from the file's actual content, not from its extension or `Content-Type`.

**Example (JSON, no photo)**

```json
{
  "name": "Mimi",
  "species": "Cat",
  "breed": "British Shorthair",
  "coatColor": "Grey",
  "dob": "2021-03-15",
  "weight": 4.2,
  "notes": "Allergic to chicken"
}
```

**Example (multipart with photo, browser)**

```js
const form = new FormData();
form.append('name', 'Mimi');
form.append('weight', '4.2');
form.append('photo', fileInput.files[0]);

fetch('http://localhost:9999/api/pets', {
  method: 'POST',
  headers: { Authorization: `Bearer ${token}` }, // do NOT set Content-Type yourself; the browser adds the multipart boundary
  body: form,
});
```

## Pet object

Every endpoint that returns a pet uses this shape.

| Field | Type | Description |
|---|---|---|
| `_id` | string | Pet id. Use it in the `:petId` path of the other pet APIs. |
| `code` | string | Unique, server-generated code, e.g. `PET-K7M2QX`. Never changes. |
| `ownerId` | string | Id of the owner (the logged-in user). |
| `name` | string | Pet name. |
| `species`, `breed`, `coatColor`, `notes` | string | Optional. The key is missing if it was never set, or `null` if it was cleared. Treat both as empty. |
| `photoUrl` | string | Optional. HTTPS URL of the photo. The key is missing if the pet has no photo. |
| `dob` | string | Optional. ISO 8601 date-time (UTC), e.g. `2021-03-15T00:00:00.000Z`. Missing or `null` if not set. Format it in UTC to avoid showing the previous day in time zones behind UTC. |
| `weight` | number | Optional. Weight in kg. Missing or `null` if not set. |
| `status` | string | `Active` or `Archived`. |
| `createdAt`, `updatedAt` | string | ISO 8601 date-times. |
| `__v` | number | Internal version key. Ignore it. |

## Responses

### 201 Created: success

```json
{
  "pet": {
    "_id": "6b1f0c2e9a3d4e5f60718293",
    "code": "PET-K7M2QX",
    "ownerId": "6ad96d4a9664da6b2c0d8d61",
    "name": "Mimi",
    "species": "Cat",
    "breed": "British Shorthair",
    "coatColor": "Grey",
    "photoUrl": "https://res.cloudinary.com/demo/image/upload/v1699999999/pets/abc123.jpg",
    "notes": "Allergic to chicken",
    "dob": "2021-03-15T00:00:00.000Z",
    "weight": 4.2,
    "status": "Active",
    "createdAt": "2026-10-27T03:15:42.123Z",
    "updatedAt": "2026-10-27T03:15:42.123Z",
    "__v": 0
  }
}
```

### 400 Bad Request: validation failed

`errors` is an array. Every problem is reported at once, one entry per problem.

```json
{
  "message": "Dữ liệu thú cưng không hợp lệ.",
  "errors": [
    { "field": "name", "message": "Tên thú cưng là bắt buộc." },
    { "field": "weight", "message": "Cân nặng phải nằm trong khoảng 0 - 500 kg." }
  ]
}
```

`errors[].field` can be `name`, `species`, `breed`, `coatColor`, `notes`, `dob`, `weight`, `photo` or `body` (the request body is not an object).

Photo problems found while parsing the upload (file too large, or the file sent under a different field name) return only a `message`, without `errors`:

```json
{ "message": "Ảnh không được vượt quá 5MB." }
```

```json
{ "message": "Tệp ảnh phải được gửi với tên trường \"photo\"." }
```

### 401 Unauthorized: missing or invalid token

```json
{ "message": "Chưa đăng nhập" }
```

```json
{ "message": "Token không hợp lệ hoặc đã hết hạn" }
```

The first is returned when the `Authorization: Bearer <token>` header is missing, the second when the token is invalid or expired.

### 500 Internal Server Error

```json
{ "message": "Lỗi máy chủ" }
```

In the rare case where a unique pet code could not be generated, the message is `Không thể tạo mã thú cưng. Vui lòng thử lại.` and the request can simply be retried.
